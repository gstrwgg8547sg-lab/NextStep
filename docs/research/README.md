# NextStep 用户验证与求职项目材料

状态：研究准备完成，尚未招募、访谈或完成真实对照评估。这里没有虚构用户、满意度或增长数据。

## 定位与待验证假设

主要目标人群：正面临实习/工作、升学/研究选择的大学生和职场新人。产品价值假设：通过明确底线、按标准对比、显示依据及未知，帮助用户看清取舍。生活场景继续支持，但不作为本轮核心招募方向。

待验证：用户是否愿意确认标准；是否理解必须与优先的区别；报告是否提供了新的有用认识；相对直接与聊天AI交流，是否减少组织信息负担；两阶段等待是否可接受。不能以“功能存在”作为价值成立的证据。

## 5–8 人探索性测试

招募当前有真实选择的人，避免只让熟悉产品的同学评价页面。使用参与者编号，不记录姓名、联系方式或公司机密。说明：可随时退出、不必提供敏感信息，分析内容会发给模型服务，录音或共享报告需另征同意。本地反馈不会自动发给开发者。

30分钟访谈流程：
1. 询问最近一次选择、现有解决方式和卡点；不先解释产品卖点。
2. 让用户自行输入真实问题、确认方案与标准并阅读报告。观察卡点，记录是否需要提示，不代填。
3. 问“请用自己的话说明当前取舍”“哪条信息需要核实”“有没有不准确或没帮助的部分”。不要问“是不是更好”。
4. 让用户修改一项真实的重要条件，查看结论是否合理响应。
5. 收集报告反馈。用户可在报告页导出已保存反馈并主动分享；导出文件没有决策正文，但自由填写的评论仍需检查敏感内容。
6. 记录最想改的一件事、等待是否影响完成任务；不要将口头好评当作留存或真实购买意愿。

每位参与者填写 sessions.csv；失败和退出也必须保留。5–8人用于发现问题，不足以证明市场规模或稳定的转化率提升。

## 与直接聊天 AI 的公平对照

分开比较两个问题：
- 内容质量：同一份最终确认信息交给 NextStep 与聊天AI；双方使用相同可用模型/设置时优先保持一致，不同则如实记载。不得只给聊天AI一句话而给NextStep完整材料。
- 使用成本：从相同原始问题开始，自然完成两种工具流程，记录补充信息、提示次数、等待及总耗时。允许用户正常追问，不人为限制一方。

将参与者顺序交替：一半先NextStep、一半先聊天AI，记录学习效应。尽量隐藏报告来源后评价内容；不能隐藏时记录偏差。统一聊天提示：“请根据以下信息帮我比较选择，说明建议、依据、关键取舍和需要核实的信息；未知不要编造。”不要求它模仿NextStep界面。

质量检查：是否违反底线、是否编造事实、事实与推断是否区分、未知是否影响选择、用户能否复述关键取舍、修改条件后是否合理更新。对于个人偏好，不预设唯一赢家；明确底线冲突等案例可以预设验收条件。不要将打分包装成模型置信度。

## 指标口径

- 独立完成率：无主持人提示完成报告阅读人数/开始人数。分别列出提示后完成、错误、退出。
- 有帮助比例：有帮助回答数/有效反馈数，同时报告未反馈人数及分母。不是“决策准确率”。
- 提取耗时：点击帮我梳理至信息确认页可用。报告耗时：提交确认信息至报告可用。
- 全流程耗时：首次提交至读到报告，包括用户填写和两阶段等待；另记录主动填写时间。
- 错误率：失败请求/全部请求；重试计新尝试，保留原失败，缓存命中单列。
- 用足够样本再统计中位数及P95，同时披露样本量、网络、模型、版本。两次请求不支持“稳定15秒”结论。
- 先完成前后同案例测试，再报告差异；结果写“观察到”，不把小样本差异直接视为因果证明。

## 下一次迭代规则

先修阻断完成或可能误导选择的问题，再修高频理解问题。若多数用户误解标准，先调整标准解释；若生活场景确认成本高，先验证更短流程，不直接新增更多场景。每次记录问题证据、选择的改动、放弃的备选、验收及结果。
